# Contract: Server Correlation Context — SPEC-010

**Status**: Draft proposal extending SPEC-002; not an authorization mechanism.

## Envelope

~~~text
CorrelationContext = {
  requestId,        // server-generated per accepted request
  turnId,           // server-generated logical turn
  correlationId,    // server-generated internal join key
  graphRunId,       // server-generated graph invocation
  conversationRef?, // opaque SPEC-003 grouping reference, not identity
  parentRef?,
  clientHint?       // isolated untrusted hint; never a canonical ID
}
ToolInvocationContext = {
  toolInvocationId, // generated by server before dispatch
  providerToolCallRef?, // untrusted provider reference, if any
  toolName,
  toolVersion,
  correlationId,
  graphRunId
}
~~~

## Rules

- SPEC-002 already proposes requestId, turnId and correlationId. This contract adds graphRunId and toolInvocationId as observability references; it does not replace SPEC-002's turn, ExecutionLedger, provider-call, or idempotency contracts.
- Every ID used for correlation is generated or validated by the server. A browser-provided value can be retained only in a separate diagnostic field under a size/format bound.
- Conversation/thread IDs group data and are not credentials, owners, principals, or access scopes.
- LangSmith run/span IDs are optional vendor references. They are mapped to internal IDs only in server-controlled metadata after field allowlisting.
- Missing parent/provider references do not create synthetic success. Each event retains its own outcome.
- All IDs are opaque in user-visible errors. No ID alone grants access to a trace, audit event, conversation, or domain record.

## Example event linkage

~~~text
requestId -> turnId -> correlationId -> graphRunId
                                  -> node span(s)
                                  -> toolInvocationId -> SPEC-002 ledger outcome
                                  -> audit event(s)
                                  -> optional LangSmith run/span references
~~~

The graph/execution ledger remains authoritative for action replay. Audit events provide operational/security evidence; LangSmith provides optional diagnostics.
